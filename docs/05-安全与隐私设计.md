# 05 · 安全与隐私设计

> 目标：局域网里其他人的电脑**看不到也进不去**你的代码和账号密码，同时你自己三台电脑之间畅通无阻。

## 四层防线

### 第 1 层：仓库级——一切皆私有

- `app.ini`：`DEFAULT_PRIVATE = private`，新建仓库（包括 devsync 自动建的）一律私有
- 私有仓库对未登录/无权限用户表现为 **404**（连"存在"都不暴露）
- 实测：无凭据 `git clone` 被拒；无凭据 API 访问返回 404（见测试 t05）

### 第 2 层：账号级——禁止注册 + 令牌认证

- `DISABLE_REGISTRATION = true` + 隐藏注册按钮：别人无法自建账号（实测注册接口被拒）
- 唯一账号 `dev` 的密码是 16 位随机字母数字，只存在枢纽机 `E:\devsync\secrets\`（本地文件，权限 600）
- git/API 操作用**令牌**（`devsync-cli`），不用主密码——令牌可随时在网页上撤销，泄露不影响账号本体
- 令牌在每台电脑上经 **Windows DPAPI 加密**保存（`%USERPROFILE%\.devsync\token.dpapi`），只有那台电脑的那个 Windows 用户能解密

### 第 3 层：网络级——防火墙网段限制

```
入站规则 "DevSync Gitea 3300"：
  协议 TCP，本地端口 3300，操作：允许
  远程IP：192.168.168.0/24, 127.0.0.1   ← 只有你的网段和本机
```

- 跨网段、外部网络的访问直接被防火墙丢弃
- Gitea 只监听局域网 HTTP，无公网暴露面；`OFFLINE_MODE` 关闭外联

### 第 4 层：传输与静态

- 传输：局域网内 HTTP 明文——被"局域网里其他人"窃听的前提是同一广播域的主动中间人，配合第 3 层网段白名单已把暴露面压到最小。若你的局域网不满足"可信内网"前提，可在 app.ini 里启用 Gitea 内置 SSH（端口 2222），git 操作全部走加密通道，文档见官方 [Windows SSH 配置](https://docs.gitea.com/zh-cn/installation/windows)
- 静态：secrets 目录（`%USERPROFILE%\.devsync-secrets`）在枢纽私库有认证保护，但**文件本身是明文**。更高机密要求：
  - 推荐开启 BitLocker 整盘加密（Windows 专业版自带）；
  - 或对 secrets 目录用 7-Zip AES-256 加密包管理，`devsync secrets push` 前手动加密。

## 与"共享文件夹"的本质区别

| | SMB 共享文件夹 | DevSync 枢纽 |
|---|---|---|
| 访问控制 | 共享权限（易配错） | 账号+令牌+私库+防火墙四层 |
| 暴露面 | 一个持续挂载的盘符 | 只在 3300 端口的 HTTP 服务 |
| 凭据存储 | Windows 凭据（明文常驻） | DPAPI 加密令牌，可撤销 |
| 审计 | 基本没有 | Gitea 完整记录谁在何时 push 了什么 |

## 已知风险与缓解

| 风险 | 缓解 |
|---|---|
| 局域网同网段的人知道地址也进不去私库，但能看到登录页 | 登录页暴露无关信息；密码 16 位随机 + 可开启失败锁定 |
| 某台电脑丢失 → DPAPI 令牌随用户账户失效，但 secrets 若在磁盘为明文 | BitLocker；丢失后立即在网页撤销该机令牌 |
| 枢纽机单点故障 | `E:\devsync\` 整目录定期拷贝到移动盘即可完整备份（含仓库+配置） |
| GitHub 仓库（公开）泄露本机信息 | 仓库入库前已脱敏：不含 IP 之外的内网细节、不含任何令牌/密码；IP 属局域网私有地址，公开无风险 |
