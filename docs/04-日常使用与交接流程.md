# 04 · 日常使用与交接流程

## 心智模型

把枢纽当成"你们仨的同事"：每次干完活 `save`（告诉他），换电脑 `take`（从他手里接），下班 `handoff`（留交接条）。

## 场景一：机器A干活 → 机器B接手（最常用）

```bash
# 机器A（干完活了）
cd E:\项目\foo
devsync save "完成了XX模块优化，测试通过"

# 机器B（接手，不用重新克隆！）
devsync take foo
# 输出：克隆/增量同步 + 自动拉取密钥 + 最近5条提交摘要
```

## 场景二：三台机器轮流接力

```bash
机器A: devsync save "v1 基础功能"
机器B: devsync take foo → 改代码 → devsync save "v2 性能优化"
机器C: devsync take foo → 改代码 → devsync save "v3 修bug"
机器A: devsync sync        # A机一条命令拿到 v2+v3，全程无需重新克隆
```

## 场景三：下班/离开电脑前的标准交接

```bash
devsync handoff "今晚做到这里：XX模块完成度80%，明天先跑测试再继续"
```

handoff 自动做三件事：
1. `save`：提交+安全推送全部代码改动
2. `secrets push`：同步密钥目录（账号密码/.env）
3. 生成交接笔记 `.devsync/handoff/2026-11-18_HHMMSS.md`（谁、哪台机器、说明、最近提交）并推送

第二天在任何一台电脑 `devsync take foo`，接手摘要里直接能看到交接笔记。

## 场景四：账号密码等敏感文件的同步

```bash
# 密钥都放这个目录（每台电脑路径相同）：
#   C:\Users\<用户名>\.devsync-secrets\
# 例如放一个 myproject.env：
#   [数据库]
#   host=192.168.168.50
#   password=...

devsync secrets push     # 推到枢纽私库 secrets-sync（仅 dev 账号可读）
devsync secrets pull     # 在另一台电脑拉下来
```

安全说明见 [05-安全与隐私设计](05-安全与隐私设计.md)：枢纽私库有认证保护，但**磁盘上是明文**，对更高要求可对该目录启用整卷加密（BitLocker）或文件级加密。

## 场景五：看看现在的全局状态

```bash
devsync status
# 枢纽: http://192.168.168.199:3300   用户: dev
#   [foo]      领先 0 / 落后 2 (有未提交改动)
#   [demo-app] 领先 1 / 落后 0
```

## 好习惯建议

1. **每次换电脑前必 save 或 handoff**——枢纽上的永远是最全的。
2. **take 后先看接手摘要**再动手，避免基于旧理解改代码。
3. **提交信息写人话**：交接笔记和提交历史是给三天后的自己看的。
4. 冲突不慌：devsync 会明确报 `RESULT: CONFLICT` 并告诉你改动在 `git stash` 里，手工裁决后 `git stash drop`。
5. 定期（比如每周）在枢纽网页上扫一眼提交图谱，确认三台机器的接力没有分叉失控。
