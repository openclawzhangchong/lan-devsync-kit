# 01 · 方案调研与选型

> 调研时间：2026-11-17 深夜。方法：搜索 CSDN / GitHub / 微软官方文档 / 知乎 / 博客园的社区实践，结合个人知识库（zhishiku）踩坑经验做交叉验证。

## 一、痛点还原

1. 三台自己的电脑轮流优化同一批 GitHub 克隆项目，换机接手必须**重新克隆**。
2. 尝试过共享文件夹 + 映射盘：**经常假死**（zcode 在映射盘上干活时卡住）。
3. 共享文件夹**没有隐私边界**：局域网里其他人的电脑也能访问秘密数据。
4. 账号密码等敏感文件**没法跟代码一起走**。

## 二、社区主流方案盘点

### 方案 A：内网自建 Git 服务器（Gitea / Forgejo / Gogs / GitLab）

**社区共识度最高的做法**。CSDN、知乎、博客园上大量教程，结论一致：

- Gitea：Go 编写、**单二进制**、内存占用小、MIT 协议，内网小团队首选（[xaoxuu 教程](https://xaoxuu.com/wiki/git/git-server)、[Gitea 官方中文文档](https://docs.gitea.com/zh-cn)、[CSDN 部署教程](https://blog.csdn.net/qq_58602552/article/details/161042174)）
- GitLab：功能全（CI/CD）但**资源消耗大**，内网 3 台电脑的场景过重（[知乎对比](https://zhuanlan.zhihu.com/p/486410391)）
- Windows 部署官方路径：下载二进制 → app.ini → **NSSM 注册服务**（[官方文档·Install on Windows](https://docs.gitea.com/enterprise/zh-cn/installation/windows)、[官方文档·Windows 服务](https://docs.gitea.com/zh-cn/installation/windows-service)、[Gitea 官方博客](https://www.cnblogs.com/Gitea/p/windows.html)）

### 方案 B：SSH 直连裸仓库（去中心化）

在固定一台机器上放 bare repo，各机 `user@machine:/path/repo.git` 直接 push/pull（[博客园](https://www.cnblogs.com/ghj1976/p/18599000/git-tong-bu-duo-tai-she-bei-mei-you-zhong-xin-cang)）。够轻，但**没有 Web 界面、权限粒度粗、Windows OpenSSH 对 git 的接线麻烦**，且"枢纽"概念弱化后交接心智负担高。

### 方案 C：Syncthing 文件级同步

P2P、TLS 加密、设备 ID 双向认证（[知乎代码同步方案](https://zhuanlan.zhihu.com/p/675821441)、[CSDN 教程](https://blog.csdn.net/i89211/article/details/147899831)、[官网](https://syncthing.net)）。**适合文档/配置，不适合活跃 git 仓库**：两台机器同时改动时 `.git` 目录可能被同步冲突弄坏，社区通行做法是排除 `.git` 只同步工作区——那就丢了版本管理。

### 方案 D：继续用 SMB 共享 + 加固

微软官方承认映射盘会空闲断连（[Windows Client 排查文档](https://learn.microsoft.com/zh-cn/troubleshoot/windows-client/networking/mapped-drive-connection-to-network-share-lost)、[Windows Server 版](https://learn.microsoft.com/zh-cn/troubleshoot/windows-server/networking/mapped-network-drive-disconnected)），社区解法全是打补丁：改注册表 KeepConn、关"自动搜索网络文件夹"、`net use * /delete` 清残留、保活脚本、NetDriveGuard 这类托盘工具（[CSDN](https://blog.csdn.net/sinat_31204593/article/details/118875705)、[NetDriveGuard](https://www.schen.space/posts/4fc5a6c4)、[Reddit 讨论](https://www.reddit.com/r/Network/comments/1p10m0t/)、[群晖 NAS 排查](https://m.qunhuinas.com/news/jishuziliao/synology_nas_yingshexinqudongqishibaihouyiyingshequdongqiduankai_5_dayuanyin_jiejuejiaocheng.html)）。

**判定：补丁式修复治不了根**。SMB 的假死来自持久会话+文件锁的模型本身，而 git over HTTP 是请求-响应式：没有挂载点、没有持久句柄、断网后重试即可，不存在"假死"这个状态。

## 三、选型结论

| 维度 | A: Gitea | B: SSH裸仓库 | C: Syncthing | D: SMB加固 |
|---|---|---|---|---|
| 换机接力体验 | ★★★ take 一条命令 | ★☆ 手敲 ssh 地址 | ★★ 文件自动到但 .git 危险 | ★★ 文件在但常假死 |
| 防假死 | ★★★ HTTP 无挂载 | ★★★ 同左 | ★★★ 无挂载 | ☆ 补丁治不了根 |
| 隐私 | ★★★ 私库+禁注册+令牌+防火墙 | ★★ 靠系统账号 | ★★★ 设备ID+TLS | ★☆ 共享权限难控 |
| 账号密码同步 | ★★★ secrets 私库 | ☆ 自己想办法 | ★★ 可同步但明文风险 | ★★ 同左 |
| Web 界面/历史/回滚 | ★★★ | ☆ | ☆ | ☆ |
| 部署复杂度（Win） | ★★ 单文件+NSSM | ★★★ | ★★ | ★ |

**最终选型：方案 A（Gitea）为主干 + secrets 独立私库补齐账号密码同步 + 防火墙网段限制 + devsync CLI 把所有动作收敛成三条命令。**

## 四、本仓库与社区方案的关系

- 沿用社区结论：Gitea + NSSM 服务 + app.ini 是 Windows 部署的标准路径；
- 超出社区教程的部分：**devsync CLI**（把 init/save/sync/take/handoff/secrets 收敛成面向"接力"语义的命令）、**冲突态拒绝再操作**的防呆、**机器可读 RESULT 行**、**secrets 私库同步**的具体实现、**防火墙网段限制**的落地、**静默提权**（ConsentPromptBehaviorAdmin=0 场景）安装细节。
