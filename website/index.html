局域网三台电脑轮流优化同一批项目：A 机干完 save，B 机 take 接手——秒级接力，永不重新克隆，账号密码一并同步，局域网里其他人进不来。
GitHub 仓库 → 快速开始 架构 命令表 测试证据

它解决什么问题

🔁

换机重新克隆

枢纽保存全部历史，devsync take 一条命令接手：没有就克隆、有就增量同步。

🧊

映射盘假死

彻底弃用 SMB 挂载。git 走 HTTP（请求-响应式，无持久句柄），不存在假死机制。

🔒

别人能看到共享

私库 + 禁止注册 + 令牌认证 + 防火墙只放行自己的网段，四层防线。

🔑

账号密码没法带走

devsync secrets 用独立私库同步 .env / 凭据，仅本人账号可读。

快速开始

① 枢纽机（一次，约 10 分钟）

powershell -ExecutionPolicy Bypass -File install\install-hub.ps1
# 产物：E:\devsync\{gitea, gitea-repos, bin, secrets}
#       + Windows 服务 DevSyncGitea（开机自启）+ 防火墙网段规则
# 管理员密码在 E:\devsync\secrets\gitea-admin.txt（勿提交到任何仓库）

② 其他电脑接入（每台一次，约 2 分钟）

# 拷贝仓库的 install\ 目录过去，然后：
powershell -ExecutionPolicy Bypass -File install\install-another-pc.ps1
# 粘贴令牌（枢纽网页 头像→设置→应用→生成新令牌，勾选 repository 读写）

③ 日常接力（就三个动作）

devsync save "完成了XX优化"      # 在干活的电脑：提交+安全推送
devsync take foo                 # 换到另一台电脑：接手（克隆/同步+密钥+摘要）
devsync handoff "下班交接"       # 可选：代码+密钥+交接笔记一键推走再走人

devsync 命令表

命令作用
devsync init [目录]把现有项目接入枢纽：自动建私库 + 首次推送
devsync clone <仓库>从枢纽克隆并登记
devsync save [说明]提交全部改动并安全推送（自动 rebase 防分叉；冲突时明确报错并教你怎么处理）
devsync sync拉取远端最新 + 推送本地
devsync take <仓库>接力核心：克隆/增量同步 + 拉取密钥 + 打印接手摘要
devsync handoff "说明"交接三件套：代码 + 密钥 + 交接笔记（.devsync/handoff/*.md）
devsync secrets push/pull同步账号密码、.env 等敏感文件（独立私库，仅本人可读）
devsync status / doctor / open状态总览 / 全面体检 / 打开枢纽网页

脚本/CI 可依赖机器可读结果行：RESULT: OK / RESULT: CONFLICT / RESULT: ERROR

安全与隐私（四层防线）

层级机制实测
仓库级新仓库一律私有，未授权者看到 404✔ t05 通过
账号级禁止注册 + 16位随机密码 + 可撤销令牌（DPAPI 加密存本机）✔ t05 通过
网络级防火墙仅放行 192.168.168.0/24 + 127.0.0.1✔ t05 通过
传输级可信内网 HTTP；不满足可启用 Gitea 内置 SSH 加密文档提供升级路径
